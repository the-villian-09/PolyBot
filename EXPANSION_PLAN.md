# PolyBot Expansion Plan

## Objective
Expand PolyBot in a disciplined order, prioritizing opportunity families that show live structural promise and delaying families that currently look noisy or weak.

## Recommended family order

### Tier 1, Build now

#### 1. Crypto threshold ladders
Why first:
- first live grouped detection
- strongest relationship logic seen so far
- compact families
- easiest path to realistic read-only and paper validation

What to support:
- threshold ordering
- nested implication checks
- multi-threshold ladder consistency
- severity ranking by inversion size

Examples:
- FDV or market cap after launch
- token price milestone ladders
- launch-related crypto threshold families

Status:
- make this the main MVP path

#### 2. Tech milestone and launch ladders
Why second:
- structurally similar to crypto
- likely to reuse threshold and by-date logic
- best adjacent family after crypto

What to support:
- milestone thresholds
- launch-by-date ordering
- event-after-launch implication chains

Rule:
- only build when the live market set has at least 2 to 3 linked contracts

### Tier 2, Add after crypto is stable

#### 3. Politics dependency logic
Why third:
- strong live coverage
- many repeated grouped families
- likely useful, but winner completeness alone looks weak

What to support:
- parent-child implications
- office-status by-date chains
- nomination/election dependency logic
- hierarchical relationships, not only summed winners

Avoid first:
- broad winner completeness scans as the main signal

#### 4. Geopolitics
Why fourth:
- sometimes has strong by-date or dependency logic
- current sample is messy and irregular

What to support:
- ceasefire by-date chains
- regime-change by-date ladders
- invasion/agreement milestone implication chains

Rule:
- only implement explicit repeated families

### Tier 3, Lower priority

#### 5. Finance
Only add if:
- repeated threshold ladders appear
- or strong related-event families show up in a larger live scan

#### 6. Economy
Only add if:
- live inventory improves
- repeated threshold or by-date structures appear

#### 7. Weather
Lowest priority until proven otherwise.

## What to ignore for now
Do not spend the next cycle on:
- generic weather logic
- broad economy scans
- broad finance scans
- more winner-family completeness checks as the main strategy

## Near-term implementation sequence
1. deepen crypto ladder logic
2. add ladder-specific ranking and persistence
3. add execution-feasibility checks
4. add tech ladder support
5. then add politics dependency logic
